# VNC页面SSE实时更新实现

> 文档状态：`archived`

## 概述

将VNC页面的轮询机制替换为Server-Sent Events (SSE)，实现后端主动推送作业状态更新，提高用户体验和系统效率。

## 实现方案

### 1. SSE管理器 (`/lib/sse-manager.ts`)

**功能：**
- 管理所有SSE客户端连接
- 提供广播功能推送作业状态更新
- 处理连接的添加和移除

**关键特性：**
- 全局连接池管理
- 支持多用户并发连接
- 自动清理断开的连接

### 2. SSE端点 (`/api/vnc/jobs/events`)

**功能：**
- 建立持久连接，推送作业状态更新
- 支持URL参数和Header两种token验证方式
- 使用SSE管理器处理连接

**关键特性：**
- 实时推送作业提交、状态变更等事件
- 自动清理断开的客户端连接
- 支持多用户并发连接

### 2. 前端SSE连接

**替换轮询逻辑：**
- 移除20秒间隔的轮询
- 建立SSE连接监听后端推送
- 收到更新事件时立即刷新作业列表

**用户体验改进：**
- 作业提交后立即显示在列表中
- 状态变更实时反映
- 减少不必要的网络请求

### 3. 作业提交广播

**VNC作业提交成功后：**
- 立即广播`job_submitted`事件
- 包含完整的作业信息
- 所有连接的客户端收到更新

## 技术优势

### 相比轮询的优势：
1. **实时性** - 状态变更立即推送，无需等待轮询间隔
2. **效率** - 减少不必要的API调用
3. **用户体验** - 提交作业后立即看到结果
4. **资源节约** - 降低服务器负载

### 实现细节：
- 使用EventSource API建立SSE连接
- 支持token验证和用户隔离
- 自动重连和错误处理
- 优雅的连接清理

## 使用方式

1. **页面加载** - 自动建立SSE连接
2. **提交作业** - 后端广播更新，前端立即刷新
3. **状态变更** - 实时推送，无需手动刷新
4. **手动刷新** - 保留手动刷新按钮作为备用

## 兼容性

- 支持现代浏览器的EventSource API
- 降级到手动刷新模式
- 保持现有API接口不变
