> 文档状态：`active`

## 功能概述

公告功能允许管理员创建、编辑和管理系统公告，用户可以在仪表盘顶部看到这些公告。

## 功能特性

### 1. 公告类型
- **信息 (info)**: 蓝色，用于一般信息通知
- **警告 (warning)**: 黄色，用于重要提醒
- **成功 (success)**: 绿色，用于成功消息
- **错误 (error)**: 红色，用于错误通知
- **维护 (maintenance)**: 橙色，用于系统维护通知

### 2. 公告属性
- **标题**: 公告的标题
- **内容**: 公告的详细内容
- **类型**: 公告的类型（影响显示样式）
- **优先级**: 0-100，数字越大优先级越高
- **启用状态**: 控制公告是否显示
- **置顶状态**: 置顶的公告会优先显示
- **开始时间**: 公告开始显示的时间
- **结束时间**: 公告结束显示的时间（可选）

### 3. 用户界面

#### 公告横幅
- 显示在仪表盘顶部
- 支持多个公告轮播显示
- 用户可以关闭单个公告
- 自动过滤过期的公告

#### 管理界面
- 访问路径: `/dashboard/system/announcements`
- 需要管理员权限
- 支持创建、编辑、删除公告
- 实时预览公告效果

## 使用方法

### 创建公告
1. 登录管理员账户
2. 进入系统管理 → 公告管理
3. 点击"新建公告"按钮
4. 填写公告信息：
   - 标题（必填）
   - 内容（必填）
   - 选择类型
   - 设置优先级
   - 配置时间范围
   - 设置启用和置顶状态
5. 点击"创建"保存

### 编辑公告
1. 在公告列表中找到要编辑的公告
2. 点击编辑按钮（铅笔图标）
3. 修改相关信息
4. 点击"更新"保存

### 删除公告
1. 在公告列表中找到要删除的公告
2. 点击删除按钮（垃圾桶图标）
3. 确认删除操作

### 管理公告显示
- **启用/禁用**: 通过开关控制公告是否显示
- **置顶**: 置顶的公告会优先显示
- **时间控制**: 设置开始和结束时间来控制公告的显示周期

## 技术实现

### 数据库表结构
```sql
CREATE TABLE announcements (
  id SERIAL PRIMARY KEY,
  title VARCHAR(255) NOT NULL,
  content TEXT NOT NULL,
  type VARCHAR(20) DEFAULT 'info',
  priority INTEGER DEFAULT 0,
  is_active BOOLEAN DEFAULT true,
  is_pinned BOOLEAN DEFAULT false,
  start_time TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
  end_time TIMESTAMP WITH TIME ZONE,
  created_by VARCHAR(100) NOT NULL,
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
  updated_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);
```

### API 接口
- `GET /api/announcements` - 获取公告列表
- `POST /api/announcements` - 创建新公告
- `PUT /api/announcements/[id]` - 更新公告
- `DELETE /api/announcements/[id]` - 删除公告

### 缓存机制
- 公告数据缓存2分钟
- 支持缓存参数控制
- 创建/更新/删除时自动清除缓存

## 最佳实践

### 1. 公告内容
- 标题简洁明了
- 内容详细但不过长
- 使用合适的类型标签
- 设置合理的优先级

### 2. 时间管理
- 设置合适的开始时间
- 及时设置结束时间避免过期公告
- 重要公告可以设置较长的显示周期

### 3. 用户体验
- 避免同时显示过多公告
- 合理使用置顶功能
- 及时清理过期或无效公告

## 故障排除

### 常见问题
1. **公告不显示**
   - 检查是否启用
   - 检查时间范围
   - 检查用户权限

2. **管理页面无法访问**
   - 确认用户具有管理员权限
   - 检查登录状态

3. **API 错误**
   - 检查数据库连接
   - 查看服务器日志
   - 验证环境变量配置

### 调试方法
1. 查看浏览器控制台错误
2. 检查网络请求状态
3. 查看服务器日志
4. 使用测试脚本验证数据库连接
