# 智能刷新策略

> 适用范围：系统模块长期知识（认证、权限、许可证、作业同步等）
> 主入口链接：`docs/README.md`
> 文档状态：`active`
> 最后验证日期：`2026-03-27`

## 问题分析

禁用自动刷新会显著提升性能，但可能影响数据实时性。需要制定智能刷新策略来平衡性能和实时性。

## 解决方案

### 1. 分层刷新策略

#### 高频刷新（实时数据）
- **活跃作业列表** (`/api/jobs/active`)
  - 刷新间隔: 15-30秒
  - 影响范围: 只查询RUNNING/PENDING作业
  - 性能影响: 较小

#### 中频刷新（重要数据）
- **当前用户作业** (`/api/jobs?user=current`)
  - 刷新间隔: 1-2分钟
  - 影响范围: 当前用户的作业
  - 性能影响: 中等

#### 低频刷新（历史数据）
- **历史作业列表** (`/api/jobs?history=true`)
  - 刷新间隔: 5-10分钟
  - 影响范围: 已完成的作业
  - 性能影响: 较大

### 2. 条件触发刷新

#### 用户操作触发
- **提交作业后** - 立即刷新当前作业列表
- **查看作业详情** - 刷新该作业的状态
- **手动刷新按钮** - 用户主动触发刷新

#### 时间触发
- **页面激活时** - 用户切换回页面时刷新
- **定时刷新** - 根据作业状态设置不同刷新间隔
- **空闲时刷新** - 用户无操作时后台刷新

#### 状态变化触发
- **有活跃作业时** - 增加刷新频率
- **无活跃作业时** - 降低刷新频率
- **作业状态变化时** - 立即刷新相关数据

### 3. 缓存策略

#### 内存缓存
```typescript
// 缓存配置
const CACHE_CONFIG = {
  activeJobs: { ttl: 15000 },    // 15秒
  userJobs: { ttl: 60000 },      // 1分钟
  historyJobs: { ttl: 300000 },  // 5分钟
  stats: { ttl: 120000 }         // 2分钟
}
```

#### 智能缓存失效
- **作业状态变化时** - 自动失效相关缓存
- **新作业提交时** - 失效用户作业缓存
- **时间过期时** - 自动失效过期缓存

### 4. 用户体验优化

#### 加载状态指示
- **显示最后更新时间** - 让用户知道数据的新鲜程度
- **刷新进度指示** - 显示刷新进度
- **状态变化提示** - 作业状态变化时给出提示

#### 手动刷新选项
- **刷新按钮** - 用户可以手动触发刷新
- **自动刷新开关** - 用户可以控制是否自动刷新
- **刷新间隔设置** - 用户可以自定义刷新间隔

## 实施建议

### 阶段1: 立即实施
1. **禁用默认自动刷新** - 提升基础性能
2. **添加手动刷新按钮** - 保持用户控制
3. **显示数据时间戳** - 让用户了解数据新鲜度

### 阶段2: 智能优化
1. **实现分层刷新** - 根据数据重要性设置不同刷新策略
2. **添加缓存机制** - 减少重复请求
3. **优化用户体验** - 添加加载状态和提示

### 阶段3: 高级功能
1. **WebSocket实时更新** - 实现真正的实时更新
2. **智能预测刷新** - 根据用户行为预测刷新需求
3. **个性化设置** - 用户可自定义刷新策略
