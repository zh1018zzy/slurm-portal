# 大屏页面与Dashboard页面数据一致性修复

> 适用范围：一次性排障、阶段总结、历史决策追溯（全项目）
> 主入口链接：`docs/README.md`
> 文档状态：`archived`
> 最后验证日期：`2026-03-27`

## 问题描述

在HPC应用系统中，大屏页面 (`/app/big-screen/page.tsx`) 和Dashboard页面 (`/app/dashboard/page.tsx`) 显示的作业累计提交数据存在不一致的问题。

## 问题分析

### 1. 数据来源不同
- **大屏页面**: 直接从数据库查询所有作业总数
- **Dashboard页面**: 从趋势数据中计算提交作业总数

### 2. 数据计算方式不同
- **大屏页面**: 使用 `supabase.from('jobs').select('*', { count: 'exact', head: true })` 获取数据库中所有作业的总数
- **Dashboard页面**: 使用 `trendData.trend?.reduce((sum: number, item: any) => sum + (item.submitted || 0), 0)` 从趋势数据中累加

### 3. 时间范围限制不同
- **大屏页面**: 查询所有历史作业
- **Dashboard页面**: 默认只查询最近30天的作业

### 4. 缓存策略不同
- **大屏页面**: 有5分钟的静态缓存
- **Dashboard页面**: 有5分钟的缓存，但缓存键包含用户和时间范围

## 解决方案

### 1. 分层数据策略

采用**分层数据策略**，让两个页面显示不同层次的数据，但使用相同的数据获取逻辑：

- **大屏页面**: 显示所有历史累计作业数量（体现系统整体使用量）
- **Dashboard页面**: 显示最近30天的作业数量（体现近期活跃度）

### 2. 创建共享数据获取逻辑

创建了 `lib/job-stats.ts` 文件，包含统一的作业统计数据获取函数：

```typescript
// 基础函数，支持可配置时间范围
export async function getJobStats(days: number = 30): Promise<JobStats>

// 获取所有历史数据 - 用于大屏页面
export async function getAllTimeJobStats(): Promise<JobStats>

// 获取最近N天数据 - 用于Dashboard页面
export async function getRecentJobStats(days: number = 30): Promise<JobStats>
```

### 3. 统一数据获取方式

- **大屏页面**: 使用 `getAllTimeJobStats()` 获取所有历史数据
- **Dashboard页面**: 使用 `getRecentJobStats(30)` 获取最近30天的数据

### 4. 统一计算逻辑

- 提交作业总数：根据时间范围从数据库中查询作业数量
- 运行时间统计：只统计已完成和运行中的作业
- CPU/GPU时间：使用数据库中的 `cpus_per_task`、`num_tasks`、`gpus_per_task` 字段

## 数据一致性保证

### 1. 统一数据源
两个页面都从同一个数据库表 (`jobs`) 获取数据

### 2. 统一计算逻辑
使用相同的字段和计算方式，只是时间范围不同

### 3. 统一错误处理
相同的错误处理逻辑和备选方案

### 4. 分层数据展示
- **大屏页面**: 展示系统整体使用情况（所有历史数据）
- **Dashboard页面**: 展示近期活跃情况（最近30天数据）

## 性能优化

### 1. 减少重复查询
共享的数据获取逻辑避免重复的数据库查询

### 2. 优化查询字段
只查询必要的字段，减少数据传输

### 3. 智能时间范围查询
- 大屏页面：一次性查询所有历史数据（低频更新）
- Dashboard页面：查询最近30天数据（高频更新）

### 4. 统一缓存策略
两个页面使用相同的缓存机制

## 注意事项

### 1. 数据更新频率
- **大屏页面**: 低频更新（5分钟），展示累计数据
- **Dashboard页面**: 高频更新（15秒），展示实时数据

### 2. 数据量差异
- **大屏页面**: 数据量大，需要优化查询性能
- **Dashboard页面**: 数据量适中，可以频繁更新

### 3. 用户权限
- 确保两个页面的数据访问权限一致
- 考虑用户角色对数据可见性的影响

### 4. 监控和维护
- 定期检查数据一致性
- 监控数据获取性能
- 及时处理数据异常

## 总结

通过采用分层数据策略，我们成功解决了大屏页面和Dashboard页面数据不一致的问题：

1. **大屏页面**: 展示所有历史累计作业数量，体现系统整体使用情况
2. **Dashboard页面**: 展示最近30天作业数量，体现系统近期活跃度
3. **数据一致性**: 两个页面使用相同的数据获取逻辑和计算方式，确保数据准确性
4. **性能优化**: 根据页面需求选择合适的时间范围，平衡数据完整性和查询性能

这种解决方案不仅修复了当前的问题，还为未来的功能扩展提供了良好的基础，避免了类似的数据不一致问题再次出现。
