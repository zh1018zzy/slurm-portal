## 当前同步机制

### 1. 智能同步API (`/api/jobs/smart-sync`)

**问题分析：**
- 强制同步逻辑不完整：即使设置 `force=true`，仍然只检查活跃作业
- 同步范围有限：只同步当前活跃的作业，不会同步已完成或失败的作业
- 历史作业状态不同步：对于已经完成的作业，状态可能不是最新的

**当前流程：**
1. 检查活跃作业（使用 `squeue`）
2. 只同步活跃作业的状态
3. 不处理历史作业的状态更新

### 2. 作业列表API (`/api/jobs`)

**问题分析：**
- 只从数据库查询，没有与Slurm实时同步
- 数据库中的作业状态可能不是最新的
- 缺少强制同步机制

**当前流程：**
1. 从数据库查询作业列表
2. 应用过滤器和分页
3. 返回数据库中的状态

### 3. 前端同步机制

**问题分析：**
- 智能同步hook被禁用（注释掉了自动同步）
- 强制同步功能不完整
- 同步后没有正确刷新数据

## 解决方案

### 1. 改进智能同步API

**需要修改的功能：**
- 支持强制同步所有作业（不仅是活跃作业）
- 使用 `sacct` 获取历史作业状态
- 同步最近7天的所有作业状态

**修改后的流程：**
1. 检查是否为强制同步
2. 如果是强制同步，查询最近7天的所有作业
3. 使用 `squeue` 获取活跃作业状态
4. 使用 `sacct` 获取历史作业状态
5. 批量更新数据库

### 2. 改进作业列表API

**需要修改的功能：**
- 在获取作业列表前先执行智能同步
- 支持跳过同步的参数
- 支持强制同步的参数

**修改后的流程：**
1. 检查是否需要同步
2. 如果有活跃作业或强制同步，执行智能同步
3. 从数据库查询最新状态
4. 返回同步后的数据

### 3. 改进前端同步

**需要修改的功能：**
- 重新启用智能同步hook
- 完善强制同步功能
- 同步后正确刷新数据

## 当前问题

1. **强制同步不工作**：即使点击强制同步，也只同步活跃作业
2. **历史作业状态不准确**：已完成、失败、取消的作业状态可能不是最新的
3. **同步机制不完整**：缺少对历史作业的状态更新

## 建议的修复步骤

1. 修复智能同步API的强制同步逻辑
2. 改进作业列表API的同步机制
3. 完善前端同步功能
4. 测试同步效果

## 技术细节

### 状态映射
- `R` -> `RUNNING`
- `PD` -> `PENDING`
- `CG` -> `COMPLETING`
- `CD` -> `COMPLETED`
- `F` -> `FAILED`
- `CA` -> `CANCELLED`

### 同步策略
- **智能同步**：只同步活跃作业的状态变化
- **强制同步**：同步最近7天所有作业的状态
- **实时同步**：在获取作业列表时自动同步活跃作业
